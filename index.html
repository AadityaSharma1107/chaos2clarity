Backpropagation maths

chain rule
Z1 = X·W1 + b1  →  A1 = ReLU(Z1)
z2 = A1·W2 + b2  →  ŷ = σ(z2)
L = −mean[ y·ln ŷ + (1−y)·ln(1−ŷ) ] + (λ/2)(‖W1‖²+‖W2‖²)
∂L/∂z2 = (∂L/∂ŷ)(∂ŷ/∂z2) = (ŷ−y)/N
∂L/∂W2 = A1ᵀ·δ2   ∂L/∂b2 = Σδ2
δ1 = (δ2·W2ᵀ) ⊙ 1[Z1>0]   (ReLU derivative)
∂L/∂W1 = Xᵀ·δ1   ∂L/∂b1 = Σδ1
W ← W − η·∂L/∂W   (or Adam)

“Gradient check” compares these formulas with numerical derivatives (L(w+h)−L(w−h))/2h.

ComplaintIQ

A customer-feedback intelligence prototype that converts unstructured complaints into categories, sentiment, urgency signals, problem groups and prioritized management insights.

Processing pipeline

Upload → Clean → Categorize → Sentiment → Urgency → Group → Rank → Dashboard → Suggested response

Core prototype rules

  • Urgency score: 0–39 Low, 40–69 Medium, 70–100 High.
  • Priority combines volume, unhappiness, urgency and recent growth.
  • Serious complaints are flagged for human review.

ML Backend

Real Python pipeline connected to this dashboard: Pandas preprocessing (clean + stopword removal) → TF-IDF features → from-scratch NumPy neural network → Scikit-learn evaluation → Matplotlib training curves. Trained on the same 90-sentence, balanced dataset as the in-browser model (sentiment_training.csv), so the two are directly comparable.

How to use this submission demo

  1. Use the included demo data to show the complete workflow.
  2. Upload a CSV with columns: id,complaint,date,product.
  3. Use Dashboard to monitor KPIs and trends.
  4. Use All Complaints to inspect individual records.
  5. Use Problem Groups to explain what should be fixed first.
  6. Use Urgent Cases and Suggested Replies to demonstrate operational value.

For a production system, connect these screens to a Python/ML backend and a database. This front end is designed to be editable and presentation-ready.
